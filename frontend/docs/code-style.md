# Стиль кода и проверки

В проекте настроены ESLint, Prettier, Husky и lint-staged для единообразного стиля и автоматической проверки кода.

## Скрипты

| Скрипт                 | Описание                            |
| ---------------------- | ----------------------------------- |
| `npm run lint`         | Запуск ESLint по всему проекту      |
| `npm run lint:fix`     | ESLint с автоисправлением (`--fix`) |
| `npm run format`       | Prettier: отформатировать все файлы |
| `npm run format:check` | Prettier: проверить без изменений   |

## Pre-commit

При `git commit` автоматически:

1. **Prettier** форматирует staged-файлы: `*.{ts,tsx,js,jsx,css,md,json}`
2. **ESLint --fix** проверяет и чинит staged-файлы: `*.{ts,tsx,js,jsx}`

Если ESLint находит ошибки, которые нельзя исправить автоматически, **коммит не пройдёт**.

## Что делать, если коммит не проходит

1. **Локально прогнать проверки:**

   ```bash
   npm run lint:fix
   npm run format
   ```

2. **Посмотреть вывод pre-commit** — там будут указаны файлы и ошибки.

3. **Исправить вручную:**
   - Используйте сообщения ESLint и ссылки на документацию.
   - Для `@typescript-eslint/no-unused-vars` — удалите неиспользуемые переменные или добавьте префикс `_`.

4. **Повторить коммит:**
   ```bash
   git add .
   git commit -m "ваше сообщение"
   ```

## Правила

- **Не форматировать весь проект в одном PR**, если задача про другое — это раздувает diff и усложняет ревью.
- Форматирование/линт в рамках изменённых файлов выполняет pre-commit автоматически.
